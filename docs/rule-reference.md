# 规则参考手册

> 适用版本：0.2.x（alpha） · UTF-8 YAML · Windows

本文按概念说明规则语法、执行行为和边界，供编写规则时查阅。第一次使用可以从[规则教程](rule-tutorial.md)开始。

示例沿用教程中的资料：`category` 是类别，`index` 是序号，`title` 是标题，`tag` 是原始标记，`label` 是扩展生成的完整标记。除标为完整规则的示例外，代码块都是对应配置的局部片段。

## 规则结构

一条规则是一个 YAML 文件。顶层字段如下：

| 字段 | 要求 | 用途 |
| --- | --- | --- |
| `name` | — | 规则名 |
| `parse` | 必填 | 解析分支列表，从原名提取字段 |
| `render` | 必填 | 输出分支列表，组合新名 |
| `transform` | 可选 | 设置解析和输出分支的默认加工链 |
| `group` | 可选 | 配置同目录文件的分组和借值 |
| `extensions` | 可选 | 将扩展能力的输出绑定为字段 |

下面是一条完整规则：

```yaml
name: organize_samples
parse:
  - template: "{category:lower} - {index=digits} - {title}"
render:
  - template: '{index:zpad(3)}_{category}_{title:trim|replace(" ", "_")}'
```

```text
Alpha - 1 - Sample A.txt  ->  001_alpha_Sample_A.txt
```

## 模板

模板由固定文字和 `{字段表达式}` 组成。解析模板对名称主体做完整匹配，固定文字及空格按原样匹配；输出模板按字段名取值并拼接，固定文字按原样输出。

模板只处理名称主体，最后一个后缀自动接回。`Alpha - 1 - Sample A.tar.gz` 的主体为 `Alpha - 1 - Sample A.tar`，后缀为 `.gz`；无后缀文件（如 `.env`）不会额外补点。模板不能指定路径，新文件仍在原目录。

模板可以只有固定文字。`render` 不清理非法字符，也不解决重名，目标名称仍须通过执行前检查。

### 定界符

可以为某个模板更换定界符。以下解析片段用于 `{Alpha} - 1 - Sample A`：

```yaml
parse:
  - template:
      text: "{<category>} - <index> - <title>"
      open: "<"
      close: ">"
```

定界符不能为空，可以包含多个字符，只作用于当前模板。不支持通过双写花括号转义；加工参数里的引号也不能保护定界符，参数含结束定界符时应更换定界符。

## 词段

词段（Token）表示提取或引用的字段，通用形式为：

```text
名称[=限定符][:加工链]
```

方括号表示可省略，不是实际语法。例如 `{index=digits:zpad(3)}` 的名称是 `index`，限定符是 `digits`，加工链是 `zpad(3)`。

### 名称与引用

名称区分大小写，必须是合法标识符；不能以数字开头，不能包含空格、短横线或点。Python 关键字可以作字段名，但无法在条件中直接引用。同一个解析模板不能重复普通字段名；输出模板可以多次引用同一个字段。

花括号只在模板里写。分组键和扩展接线直接写 `index=int`、`tag:lower` 等表达式；条件直接写字段名，字面文本才加引号。

### 限定符在不同位置的含义

| 位置 | 示例 | 含义 |
| --- | --- | --- |
| 解析模板 | `{index=digits}` | 限定捕获字符；保存的仍是文本 |
| 分组键 | `index=int` | 转换保存值，用于划分 |
| 输出模板 | `{index=digits:zpad(3)}` | `=` 不校验字符，只执行加工；通常省略 `=digits` |
| 扩展接线 | `index=int` | 不会自动把普通文本端口变成整数端口 |

`digits` 与 `int` 不能互换。

### 字符类别与匹配边界

| 类别 | 接受的字符 |
| --- | --- |
| `digits` | ASCII 数字 `0`–`9` |
| `en` | ASCII 英文字母，不含空格 |
| `cn` | U+4E00–U+9FFF 的汉字 |
| `en/digits` | 字母或数字；`/` 表示并集 |

不需要限定时省略整个 `=...`，不要写空的 `=`。类别不声明长度，也不转换类型。

如果同一份资料的类别和序号紧贴着写成 `Alpha1`，不同模板会产生以下结果：

| 模板 | category | index |
| --- | --- | --- |
| `{category}{index}` | `A` | `lpha1` |
| `{category}{index=digits}` | `Alpha` | `1` |
| `{category=en}{index}` | `A` | `lpha1` |
| `{category=en}{index=digits}` | `Alpha` | `1` |

匹配采用非贪婪方式，前面的字段尽量少取；`en` 不要求取完连续字母。相邻字段应通过分隔文字或字符类别建立明确边界。两个相邻数字字段也不会自动按固定宽度切分：`{left=digits}{right=digits}` 将 `0102` 分成 `0` 和 `102`。

加工失败不会触发重新切分；字符类别也不会在加工后重新校验。

匹配先确定原文边界，再执行词段加工。`{index=digits:trim}` 不能接收带空格的数字片段，因为空格在匹配时已不符合类别。

### 忽略片段

如果资料前面的标记不需要用于条件或输出，可以使用：

```text
[{_}] {category} - {index} - {title}
```

`{_}` 匹配并丢弃非空文本，不表示可选片段。可以多次使用，也可以写 `{_=digits}`；不能附加加工链，不能用于输出、分组或扩展接线。

## 分支

`parse` 和 `render` 都是分支列表。每个分支必须有 `template`，可以有 `transform` 和 `condition`：

```yaml
parse:
  - template: "{category} - {index=digits} - {title}"
    transform: trim|lower
    condition: 'file.suffix == ".txt"'
```

### 解析分支选择

解析分支不会按列表顺序选第一条。所有分支都会尝试完整匹配，再比较匹配成功的分支：固定文字越多、受限字段的捕获越长，约束越强。未限定字段、字段名和列表顺序不影响选择。

最高分唯一时选中该分支；最高分并列会报错。应通过固定文字或字符类别区分格式，调整列表顺序或字段名不能消除并列。

一个模板不匹配时，其他分支仍可接手；所有解析分支都不成立时，当前文件失败，同批次其他文件继续处理。加工、条件或取值报错则不会通过改选其他分支重试。

解析条件为假的分支不参与选择；条件不增加分支得分，条件报错会让当前文件失败。

例如，`{category} - {index=digits} - {title}` 与 `{category} - {index=digits} - {title} [{tag}]` 都能匹配 `Alpha - 1 - Sample A [A]`。后者有额外的固定文字，约束更强，选中后得到 `title=Sample A`、`tag=A`。

### 输出分支选择

字段来源可以是当前解析分支的捕获、扩展输出，或同组其他文件的借值。

输出分支先检查所需字段有没有来源，再检查条件。在候选分支中：

- 恰好一个条件为真时，使用该分支；此时无条件分支不参与选择。
- 没有条件为真时，必须恰好有一个无条件分支作为兜底。
- 多个真条件、多个兜底或没有可用分支，都会报错。

输出分支也不会首次命中就停止。条件报错不会改用兜底分支。

例如，以下片段为标记 A 选择特殊输出，其余使用无条件分支：

```yaml
render:
  - template: '{index:zpad(3)}_{category}_{title:replace(" ", "_")}.marked'
    condition: 'exists(tag) and tag == "A"'
  - template: '{index:zpad(3)}_{category}_{title:replace(" ", "_")}'
```

### 执行次序

解析分支：分支加工 -> 模板匹配 -> 词段加工并保存 -> 条件检查。条件无法阻止前面的加工错误。

输出分支：检查字段来源和条件 -> 拼接时加工每次字段引用 -> 拼接后执行分支加工。输出加工不改变条件读取的保存值。

## 加工链

加工链用 `|` 连接操作，从左到右执行。例如 `{title:trim|replace(" ", "_")}` 将 `" Sample A "` 变为 `"Sample_A"`。

### 操作与参数

| 操作 | 用途与约定 |
| --- | --- |
| `trim` | 去掉首尾空白 |
| `lower` / `upper` | 转小写 / 大写 |
| `capitalize` | 首字符大写，其余小写 |
| `replace("old", "new")` | 替换全部对应子串；旧串不能为空 |
| `zpad(3)` | 补到至少三位；宽度为 0–10000 的整数，保留符号，不截短长文本，空串仍为空串 |
| `date_format("%Y-%m-%d", "%Y.%m.%d")` | 按输入格式读取日期，再按输出格式生成 |

每个操作接收并返回文本。无参操作可以写 `lower` 或 `lower()`；参数只接受常量位置参数，不能引用其他字段、使用关键字参数或计算表达式。字符串参数中的 `|` 不拆分加工链，空字符串表示不加工。

`date_format` 支持指令字母 `a A b B c d H I j m M p S U w W x X y Y f z Z G V u` 以及 `%%`，其他指令和非法日期会报错。

### 执行位置与默认值

| 位置 | 何时执行 | 影响什么 |
| --- | --- | --- |
| 解析分支 `transform:` | 匹配前 | 整个原名主体 |
| 解析字段 `{title:trim}` | 捕获后 | 保存值 |
| 输出引用 `{title:upper}` | 拼接该引用时 | 本次输出，不改保存值 |
| 输出分支 `transform:` | 拼接完成后 | 整个新名称主体 |

上述加工均不包含最后一个后缀。解析条件在解析加工之后检查；输出条件在输出加工之前检查。

顶层 `transform` 为对应分支设置默认加工链，例如：

```yaml
transform:
  parse: trim|lower
  render: 'replace(" ", "_")'
```

分支未写 `transform` 或写 `null` 时继承默认值；写 `transform: ""` 时关闭；写其他链时完整替换默认链，不会追加。字段上的加工独立执行，不受继承和覆盖影响。

`zpad` 只按文本补零，不校验数字：`abc` 经 `zpad(5)` 得到 `00abc`。

## 条件

条件是写在解析或输出分支 `condition` 中的单行表达式，只决定分支是否可用，不修改字段。

条件读取保存的字段值。如果解析模板使用了 `category:lower`，条件中应比较 `category == "alpha"`；输出引用上的 `:upper` 等加工不会改变条件读到的值。

数字字段也是文本，应写 `index == "1"`。比较区分大小写，不会自动去空白或转换类型。

存在也不等于非空。`[ ]` 中的空格经 `tag:trim` 处理后得到空字符串，`exists(tag)` 仍为真；需要非空标记时，使用 `exists(tag) and tag != ""`。

### 运算与文件属性

| 写法 | 含义 |
| --- | --- |
| `index == "1"` / `index != "1"` | 相等 / 不等 |
| `tag in ["A", "B"]` | 属于候选列表 |
| `tag not in ["A", "B"]` | 不属于候选列表 |
| `"Sample" in title` | 包含子串 |
| `exists(tag)` | 字段存在，不保证非空 |
| `file.suffix == ".json"` | 比较原文件属性 |
| `A and B` / `A or B` / `not A` | 与 / 或 / 非；A、B 代表条件表达式 |

条件必须是非空单行表达式。可用值是字段、下列文件属性、字符串和字符串列表。支持的运算仅为表中列出的运算；不支持大小比较、连续比较及 `exists` 以外的函数调用。`and` 遇假停止，`or` 遇真停止；直接读取缺失字段会报错。

| 属性 | 内容 |
| --- | --- |
| `file.path` | 原文件绝对路径 |
| `file.name` | 带后缀的原文件名 |
| `file.stem` | 去掉最后一个后缀的主体 |
| `file.suffix` | 小写的最后一个后缀，包含点 |
| `file.parent` | 父目录路径 |
| `file.parent_name` | 父目录名称 |

属性始终来自原文件，不能在模板中写成 `{file.name}`，也不能作为分组键或扩展接线。判断有无后缀应写 `file.suffix != ""`，因为无后缀时 `exists(file.suffix)` 也为真。

路径按文本比较，反斜杠需要遵守条件字符串的转义规则：路径 `C:\work\a.txt` 的比较写成 `'file.path == "C:\\work\\a.txt"'`。

## 分组

分组关联同一规则、同一父目录中的文件，供缺少字段的文件读取同组成员的值，不跨子目录。供值文件与借值文件必须在同一次运行中处理。

### 分组键

`group` 可以列出多个备选项。每项指定一个分组键：

```yaml
group:
  - token: index=int
    partition: equal
  - token: title:trim|lower
```

每个文件选用第一个存在且非空的捕获；选用同一列表项的文件，再按键值划分。这不是把序号和标题组合成一个键。

键的处理顺序是：读取捕获 -> 键加工 -> 类型转换 -> 划分。空白文本也会被选中；即使键加工后变成空串，也不会改选下一项。转换或划分失败时，不尝试备用键；同一规则、同一父目录中选用该列表项的文件一起接受转换和划分，其中一个失败，这些文件的分组均失败。

未配置分组，或所有备选捕获都缺失、为空时，文件独立成组。

分组键读取解析保存值，解析字段上的加工已经生效。键上的加工和转换另做一层，不改写原字段。

### 借值

已有本地捕获或本地扩展输出时，使用本地来源；没有本地来源时才借用其他组员的值。本地扩展失败不会自动改为借值。

借值需要其他成员提供的真实来源全部取值成功，并且文本一致。例如同组两个来源分别提供 `Sample A` 和 `Sample B`，无法据此确定标题。借来的值不会成为新的真实来源；来源文件输出失败也不一定影响该文件提供字段值。

例如，`Alpha - 1 - Sample A.txt` 提供 `category`、`index`、`title`，`Alpha - 01.json` 只提供 `category`、`index`。按 `index=int` 分组后，两者的键都是整数 1，JSON 可以借到 `title=Sample A`。

键相等不代表原字段文本相等：`1` 与 `01` 可同组，但如果作为借值的多个来源，文本仍不一致。本地序号不受分组转换影响，输出仍需自行补零。

### 类型转换与划分方式

当前类型转换仅支持 `int`，按 Python 十进制整数规则处理，接受符号和首尾空白，不接受 `1.5` 等小数文本。不转换时省略 `=...`，不写 `=string` 或空的 `=`。

| `partition` 写法 | 含义 |
| --- | --- |
| `equal` | 默认方式，按值相等分组，接受文本和整数 |
| `edit_distance(1)` | 按字符串编辑距离划分，只接受文本 |
| `any(...)` | 合并任一子划分中的同组关系 |
| `all(...)` | 只保留所有子划分共同的同组关系 |

`edit_distance` 参数为非负整数，表示单字符插入、删除或替换的最大次数，比较区分大小写，不能与整数键搭配。文件依次加入第一个与组内每个成员都符合阈值的组，不沿相似链自动合并；结果可能受输入顺序影响，CLI 按完整路径字符串排序。

例如按类别分组时，`Alpha` 与 `Alphb` 在 `equal` 下不同组，在 `edit_distance(1)` 下可以同组。是否应当关联，取决于这两个类别名称在实际资料中是否确实指向同一类别。

`any` 会传递合并关系：一个子划分关联 A、B，另一个关联 B、C，最终三者同组。`all` 要求所有子划分都认可同组关系。两者至少包含一个子划分器，允许嵌套，例如 `all(equal, edit_distance(1))`。

## 扩展

扩展把已有字段接到能力的输入端口，再将输出绑定为新字段。结果可用于条件、输出模板或其他扩展。

### 接线

```yaml
extensions:
  - name: builtin:lookup
    inputs:
      value: "tag:trim|lower"
    outputs:
      value: label
    options:
      reviewed: [a, a1, reviewed]
      draft: [b, b1, draft]
```

- `name` 选择要使用的能力，这里是内置查表能力。
- `inputs` 把字段接到输入端口。左边的 `value` 是能力规定的端口名；右边的 `tag:lower` 表示读取标记并转成小写。
- `outputs` 把输出端口绑定为字段。这里把返回值保存为 `label`，随后可以用 `{label}` 引用。
- `options` 配置查表关系。键是目标文本，列表是可以接受的别名。

接线中的字段不加花括号。输入加工在调用前执行，输出也可以写成 `label:upper`，在返回后加工。

输入端口必须完整绑定；没有普通输入的能力可以省略 `inputs`。输出只绑定需要的端口，各端口的目标字段名不能重复。普通端口传递文本，`=int` 不改变端口类型。

节点不能添加 `condition`、系统字段或资源字段。需要按条件选择输出时，在 `render` 分支中配置条件。

### 内置能力

`builtin:map` 的输入、输出端口均为 `value`，原样传递输入，加工由端口上的链完成。例如输入 `tag:trim|lower`、输出 `normalized_tag`，可保留规范化标记供多个位置使用。

`builtin:lookup` 的输入、输出端口均为 `value`，按完整文本查表。`options` 的键是目标文本，值是接受的别名列表。上面的配置将标记 `A` 先变为 `a`，再查得 `reviewed`。

查表本身不清理空白或大小写。目标文本不会自动加入对应的别名列表，需显式加入列表。未列出的输入报错，不原样返回。目标和别名必须是非空字符串，别名列表不能为空；同一别名不能对应两个目标，同一目标内允许重复别名。只查表一次，不递归替换。

### 依赖与执行

如果多个地方要共用规范化后的标记，可以先用 `builtin:map` 生成 `normalized_tag`，再交给查表节点。两个节点的接线如下：

```yaml
extensions:
  - name: builtin:map
    inputs:
      value: "tag:trim|lower"
    outputs:
      value: normalized_tag
  - name: builtin:lookup
    inputs:
      value: normalized_tag
    outputs:
      value: label
    options:
      reviewed: [a, a1, reviewed]
      draft: [b, b1, draft]
```

`map` 原样传递输入，具体加工来自接线上的加工链。这里的依赖是：

```text
tag  ->  map  ->  normalized_tag  ->  lookup  ->  label
```

执行顺序由依赖决定，不由书写顺序决定。条件和选中的输出模板需要某个字段时，才沿依赖取值；同一文件、同一节点在一次运行内复用结果或失败。

未被需要的节点不执行数据处理，但能力名称、端口和所需资源仍须有效。多输出节点一旦触发，会处理所有已绑定输出；任一输出加工失败，节点失败。

不支持多个适用节点为同一文件生成同名字段，也不能形成循环依赖。已有捕获优先于同名扩展输出；输入和输出使用同一字段名不能实现原地覆盖。节点因其他输出触发时，同名结果不同会报冲突。

### 外部能力

外部插件沿用相同的接线方式，能力名称、端口和 `options` 由插件定义。插件通过 `sr.plugins` 入口注册，必须安装在运行 `sr` 的环境中；仅在 YAML 中填写名称不会安装插件。
